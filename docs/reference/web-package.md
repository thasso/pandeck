# Web package — implementation reference

Relocated from `app/web/CLAUDE.md` (Task-274) so it stops costing agent context
on every visit. This is a descriptive snapshot of what the modules in that
subtree own; the rules an agent must not violate stay in that folder's
`CLAUDE.md`. Correct or delete a section here when the code moves on. Relative
paths in the body are relative to the original subtree.

## Purpose

Vite/React browser client for chat sessions, settings, project/task management,
calendar views, tool cards, and PWA assets.

## Module ownership

- `src/` owns application UI source.
- `docs/ui-shell.md` owns the binding UI shell concept (three-pane layout,
  navigation rules, object linking, the right object panel — a single Details
  inspector whose "Start a new session" action lands on the new-session page
  with context pre-staged — and the small-screen **screens** model: a section
  index route is the browser screen, every other route is an object screen with
  a back control to the selected section's index route).
- `public/` owns static PWA assets copied into production builds; `sw.js` uses
  network-first navigation so deployments do not leave the SPA shell stale,
  while hashed assets remain cache-first. Current-iOS Declarative Web Push is
  window-managed and navigates directly from its payload, so `sw.js`
  deliberately has no push or notification-click handlers.
- `index.html`, `vite.config.ts`, `tsconfig.json`, and `package.json` own web
  package configuration.
- `dist/` is generated by builds and is not source.

## Contract notes and rationale

- Follow `docs/ui-shell.md` for any change to the app shell, sidebar, routing,
  or page composition.
- Keep client protocol shapes imported from `@assistant/shared`.
- Maintain strict TypeScript and Vite-compatible browser code; no Node-only APIs
  in UI source.
- `vite.config.ts` defines `__ASSISTANT_BUILD__` from
  `app/server/src/buildInfo.ts` — the bundle's own version and commit, resolved
  once at build time because a loaded bundle cannot ask. It is the same resolver
  the server uses, which is what makes the two rows in Settings → About
  comparable; `lib/appBuild.ts` is the only reader (`docs/ci-cd.md`).
- `vite.config.ts` forces `NODE_ENV=development` for `command === "serve"`. Vite
  reads `isProduction` from the ambient `NODE_ENV` and only defaults it when
  unset, so a dev server started from a shell that exports `NODE_ENV=production`
  (agent sessions inherit it from the deployed systemd unit) loses the Fast
  Refresh preamble while the JSX transform still emits `$RefreshSig$()` — a
  blank page. Keep that guard.
- Preserve auth token handling through existing `serverOrigin` helpers for
  API/WebSocket calls.

## Working notes

- Prefer lazy loading for heavy route pages and rich domain tool cards.
- Keep Vite chunks under the 500 KB source budget; lazy Shiki grammar/wasm data
  chunks (loaded per language on demand) have an 800 KB allowance via
  `vite.config.ts`.
- Keep generated assets out of source changes unless intentionally updating
  `public/`.
- `vite.config.ts` `build.assetsInlineLimit` deliberately excludes the dictation
  AudioWorklet (`src/lib/pcm16Worklet.js`) from inlining: it is under the inline
  threshold, and an inlined `data:text/javascript` URL is not reliably accepted
  by `audioWorklet.addModule()`. Verify worklet-style assets in a real
  production build, not just in dev.

## Verification commands

- Run `pnpm --filter @assistant/web test` for web unit tests.
- Run `pnpm --filter @assistant/web test:kb` for focused Knowledge
  routing/rendering/inspector tests.
- Run `pnpm --filter @assistant/web build` for web changes.
- Run root `pnpm run build` before closeout.
- Run root `pnpm run typecheck` if shared/server contracts are affected.
